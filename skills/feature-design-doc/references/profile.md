# 本机配置（profile）

技能本身不放任何产品、公司或团队的专有信息。这些信息写在本机的配置目录里，换产品时换配置，技能不用改：

```text
~/.config/feature-design-doc/          # 可用环境变量 FEATURE_DESIGN_DOC_HOME 换位置
├── profile.md                         # 给 agent 读：产品、代码在哪、服务路由、团队模板
├── config.json                        # 给构建脚本读：默认皮肤、三方名称
└── skins/
    ├── <皮肤名>.css                    # 产品皮肤：照真实后台做的复刻
    └── <皮肤名>.js
```

开始写文档前先读 `profile.md`；构建脚本自动读 `config.json` 和 `skins/`。

## profile.md 写什么

```markdown
# 产品配置：<产品名>

- 产品：<一句话：这是什么系统，谁在用>
- 服务与仓库：<服务名、仓库路径、负责什么>；服务路由说明见 <文件路径>
- 前端：<前端仓库路径>；路由配置在 <文件>；表单组件在 <目录>
- 原型皮肤：<皮肤名>（skins/ 下），主题色 <色值>
- 代码引用的仓库标签：[member]、[marketing]、……
- 团队技术方案模板：<章节对应关系>；需要导出到其他文档系统时用 <工具或技能>
- 不写进文档的团队通用规范：<比如日志格式、脱敏、压测出网拦截>
```

## config.json

```json
{
  "skin": "my-console",
  "parties": ["支付平台", "短信平台"]
}
```

- `skin`：原型的默认皮肤；文档头的 `skin:` 优先。
- `parties`：三方负责方的名称，正文里的【支付平台】会渲染成三方标签。文档头的 `parties:` 会再追加。

## 产品皮肤

照真实后台做一套皮肤，原型才能和线上页面一致：

1. 复制技能里的 `assets/skins/admin.css`、`admin.js`，改名为 `<皮肤名>.css`、`<皮肤名>.js`，放进 `skins/`。
2. 对照前端代码改：主题色、顶栏和侧栏的尺寸、logo、菜单结构、表单的标签宽度和间距、常用的复合组件（比如消息预览、配置卡片）。
3. 保持同样的函数名（`SKIN.app`、`SKIN.item` ……），并在文件末尾保证 `window.SKIN` 指向皮肤对象。这样模板和已有的原型脚本都不用改。
4. 新的复合组件写进皮肤 CSS，并在 profile.md 里列出类名和用法。

构建时皮肤按这个顺序查找：文档同目录的 `skins/` → 本机配置的 `skins/` → 技能自带的 `assets/skins/`。
