# 决策记录

决策记录是方案里每个关键取舍的记录：当时要解决什么问题、选了什么、为什么、代价是什么、哪些做法没选。它让没参加讨论的人也能明白方案为什么长这样，也让后来改设计的人先看到前因。

模板：`templates/decisions.md`。语法见 `components.md` 的「决策」。

## 什么时候加一条

- 技术方案里每个关键取舍：复用还是新建、同步还是异步、批量还是实时、幂等键怎么定。
- 讨论中用户拍板的事：某个字段不做、某个交互怎么改、这次不做缓存。写明谁定的、哪天。
- 待确认项（B、D）有了结论：加一条记录，并把需求设计或技术方案里对应的行改成【已确认】、写上「见决策 N」。

## 怎么写

- **只往后加，不改写。** 结论变了就加一条新记录，旧记录标【被替代】并写明被哪条替代；撤销的标【已撤销】。编号不复用。
- **每条写全七项。** 状态、日期、背景、选择、理由、代价、未采用，最后是关联（B、G、§、P 编号）。
- **背景要能单独读懂。** 没参加讨论的人读完这一段，要能明白为什么要做这个决定：PRD 怎么要求，现状和约束是什么，不处理会怎样。
- **理由带数字和依据。** 「每天约 3 千人，一次批量 2 秒内完成【推断】」比「性能更好」有说服力；代码事实写 `[仓库] 文件:行号`。
- **代价写清和 PRD 预期不一样的地方。** 测试从这里知道哪些验收用例要改。
- **状态。** 【已确认】【待确认】【被替代】【已撤销】；【待确认】写明等谁确认什么（B 编号）。
- **一览表。** 第 0 章列出所有决策的编号、标题、状态、等谁或谁定的、关联，读者先看一览再看详情。
